## Архитектура v1

- Vanilla JS, IIFE, рендер через `innerHTML`-шаблоны, хэш-роутинг (`#dashboard`, …).
- Всё состояние — один JSON в `localStorage['qarajat_v9']`.
- Разделы: Главная, Операции, Аналитика, Календарь, Счета, Долги, Цели, Категории, Капитал, Уведомления, Профиль, AI-помощник «Алдар-Косе» (локальные шаблонные ответы, без сети).

### Модель данных `qarajat_v9` (используется для миграции)

- `accounts[]`: `{id, name, kind: available|savings|investment, initial, bankId, type: card|current|deposit|credit|installment, currency, status}`
- `operations[]`: `{id, type: income|expense|transfer|adjust, amount, date, accountId, toAccountId?, category (имя!), comment, status: done|plan|cancel}`
- `debts[]`: `{id, name, type: 'Кредит'|'Рассрочка'|'Ипотека'|…, initial, balance, rate, minPayment, payDay, accountId, startDate, endDate, status, payments[]}`
- `goals[]`: `{id, name, emoji, target, saved, date, priority, accountId}`
- `recurring[]`: `{id, name, amount, type, category, accountId, interval, nextDate, dayOfMonth, status}`
- `events[]`, `categories{income[], expense[]}`, `profile{name, avatar(dataURL), birthDate…}`, `settings{salaryDay, reserveForGoals, expectedIncome, minReserve}`

## Найденные проблемы

### Критические (данные и расчёты)
1. **Демо-данные с вымышленными суммами при первом запуске** (`seed()`: счета на 3,4 млн ₸, кредиты, цели). Пользователь не может отличить их от реальных; противоречит ТЗ.
2. **Суммы во float** — накопление ошибок округления; нет учёта тиынов.
3. **Остаток долга хранится отдельно от операций.** `payDebt` уменьшает `debt.balance` и создаёт операцию-расход; при редактировании/удалении этой операции остаток долга не пересчитывается → рассинхрон и риск двойного учёта.
4. **Проценты по долгу** считаются как `balance × rate/12` при любом платеже, без различия регулярного и досрочного; нет графика (аннуитет/дифференцированный), нет режима «уменьшить срок / платёж».
5. **Цели:** `goal.saved` и перевод на счёт живут отдельно — удаление перевода не меняет накопленное.
6. **Корректировка баланса** (`adjust`) задаёт абсолютное значение — результат зависит от порядка операций с одной датой.
7. **Safe-to-spend** вычитает `reserveForGoals = 150 000 ₸` из демо-настроек; использует «последние 30 дней» вместо календарного месяца; отрицательный результат обрезается до 0 без предупреждения.
8. **Хранилище:** `localStorage` (~5 МБ) + аватар в base64 → переполнение; при ошибке данные остаются только в памяти и пропадают после перезагрузки.
9. **Импорт JSON** проверяет только наличие массивов `accounts`/`operations`, поля записей не валидируются.

### Функциональные
10. Календарь показывает только текущий месяц, нет недельного вида и навигации; платежи по долгам отображаются даже после оплаты; регулярные платежи нельзя подтвердить.
11. Регулярные доходы в календаре помечаются как «Расход».
12. Нет фото чеков, тегов, подкатегорий в операциях, документов к долгам, фото целей, обрезки аватара.
13. Экспорт JSON не содержит вложений (аватар — base64 внутри состояния).
14. Рекомендации AI-помощника — шаблонные ответы, не персональный анализ.

### Технические / PWA
15. `index.html` ссылается на `icons/icon-192.png`, `icon-512.png`, `apple-touch-icon.png` — таких файлов нет (есть только `*-v2.png`).
16. Иконки весят ~2 МБ каждая и не квадратные — замедляют установку PWA.
17. `banks.js` не используется, но кэшируется service worker.
18. Рендер через `innerHTML` — в целом с экранированием (`esc()`), но архитектура хрупкая для XSS.

## Что сохраняем из v1
- Справочник банков Казахстана (20 банков с цветами).
- Набор категорий доходов/расходов.
- Логику `advanceRecurring` (перенос на последний день короткого месяца).
- Принцип «переводы не являются доходом/расходом».
- Возможность миграции данных `qarajat_v9` (тот же origin `almakhanoff.github.io` → v2 может прочитать данные v1 с согласия пользователя).

## Решения для 2.0
- React + TypeScript + Vite, Tailwind CSS, Lucide, Recharts, IndexedDB (`idb`), PWA (`vite-plugin-pwa`).
- Суммы — целые числа в тиынах.
- Остатки счетов, долгов и накоплений **вычисляются** из истории, а не хранятся отдельно.
- Платёж по долгу = одна запись платежа + одна связанная операция (удаление одного удаляет другое).
- Цели — резервирование средств на счетах, а не отдельные деньги (не увеличивают капитал).
- Отдельная база `qarajat2` в IndexedDB, данные v1 не изменяются и не удаляются.
- Без демо-данных: пустые состояния с подсказками.
